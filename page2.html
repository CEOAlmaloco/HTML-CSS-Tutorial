Introducción a las Buenas Prácticas

Desarrollar con buenas prácticas en HTML y CSS es fundamental para crear sitios web mantenibles, accesibles, eficientes y seguros.

¿Por qué son importantes?

  • Mejor rendimiento del sitio
  • Código más fácil de mantener
  • Mejor posicionamiento SEO
  • Mayor accesibilidad
  • Mayor seguridad
  • Compatibilidad entre navegadores

Estructura Básica y Organización

1. DOCTYPE Correcto

Siempre incluye el DOCTYPE de HTML5 al principio de tus documentos:

<!DOCTYPE html>

2. Estructura de Carpetas

Organiza tus archivos de forma lógica:

proyecto/ ├── index.html ├── styles/ │ ├── main.css │ └── reset.css ├── assets/ │ ├── img/ │ └── fonts/ └── scripts/ # Para JavaScript externo

3. Metadatos Esenciales

Incluye estos metadatos en el <head>:

<meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Título descriptivo de la página</title> <meta name="description" content="Descripción del contenido">

Mala Práctica: CSS/JS en el mismo archivo HTML

Evita incluir grandes cantidades de CSS o JavaScript directamente en tu HTML:

<!-- MALA PRÁCTICA --> <style> /* Mucho CSS aquí */ </style> <script> // Código JavaScript aquí </script>

Esto dificulta el mantenimiento, reduce la reutilización y puede afectar el rendimiento.

HTML Semántico

1. Usa Elementos Semánticos

Prioriza elementos que describan su contenido:

<header>, <nav>, <main>, <section>, <article>, <aside>, <footer>, <figure>, <figcaption>, <time>, <mark>, etc.

Ejemplo de Estructura Semántica

<body> <header> <nav>...</nav> </header> <main> <article> <h1>Título</h1> <section>...</section> </article> <aside>...</aside> </main> <footer>...</footer> </body>

Mala Práctica: Uso Excesivo de Divs

Evita crear "divitis" - usar divs en exceso sin significado semántico:

<!-- MALA PRÁCTICA --> <div id="header">...</div> <div class="nav">...</div> <div id="content">...</div> <div class="footer">...</div>

Organización de CSS

1. Enlace Correcto de Hojas de Estilo

Coloca los enlaces a CSS en el <head>:

<head> <link rel="stylesheet" href="styles/main.css"> </head>

2. Estructura de Archivos CSS

Organiza tu CSS en secciones lógicas:

/* ===== VARIABLES ===== */ :root { --primary: #2c3e50; --secondary: #3498db; /* ... */ } /* ===== RESET Y BASE ===== */ * { /* ... */ } body { /* ... */ } /* ===== COMPONENTES ===== */ .button { /* ... */ } .card { /* ... */ } /* ===== LAYOUT ===== */ .container { /* ... */ } .grid { /* ... */ } /* ===== PÁGINAS ESPECÍFICAS ===== */ .home-hero { /* ... */ } /* ===== MEDIA QUERIES ===== */ @media (max-width: 768px) { /* ... */ }

3. Metodologías CSS

Considera usar metodologías como:

BEM (Block, Element, Modifier)

.block { /* Estilos */ } .block__element { /* Estilos */ } .block--modifier { /* Estilos */ }

SMACSS (Scalable Modular Architecture)

Base, Layout, Module, State, Theme

Mala Práctica: Estilos en Línea

Evita el uso de estilos en línea:

<!-- MALA PRÁCTICA --> <div style="color: red; font-size: 20px;">...</div>

Esto dificulta el mantenimiento, viola la separación de preocupaciones y aumenta la especificidad innecesariamente.

Optimización de Rendimiento

1. Minimiza y Comprime Archivos

En producción, usa versiones minificadas de tus archivos CSS:

styles/ ├── main.css # Para desarrollo └── main.min.css # Para producción (minificado)

2. Usa CSS Efficiente

  • Evita selectores demasiado específicos
  • Reduce el uso de !important
  • Agrupa propiedades similares
  • Usa propiedades que no causen repaint/reflow

3. Optimización de Imágenes

Para imágenes de fondo:

/* Usa formatos modernos */ background-image: url('imagen.webp'); /* Especifica dimensiones */ background-size: cover; /* Optimiza carga con lazy loading */ /* Para imágenes en contenido: */ <img src="imagen.jpg" loading="lazy">

Consideraciones de Seguridad

1. Enlaces Seguros

Para recursos externos, usa siempre HTTPS:

<!-- BUENA PRÁCTICA --> <link rel="stylesheet" href="https://dominio.com/estilos.css"> <!-- MALA PRÁCTICA --> <link rel="stylesheet" href="http://dominio.com/estilos.css">

2. Atributos de Seguridad

Para enlaces que abren en nuevas pestañas:

<!-- BUENA PRÁCTICA --> <a href="https://externo.com" target="_blank" rel="noopener noreferrer"> Enlace externo </a> <!-- MALA PRÁCTICA --> <a href="https://externo.com" target="_blank"> Enlace externo </a>

rel="noopener noreferrer" previene ataques de tipo tabnabbing.

3. CDNs con Subresource Integrity (SRI)

Al usar recursos de CDNs, implementa SRI:

<link rel="stylesheet" href="https://cdn.example.com/style.css" integrity="sha384-...hash..." crossorigin="anonymous">

Esto asegura que el recurso no haya sido modificado maliciosamente.

Precaución con JavaScript

Aunque no es el foco de esta guía, recuerda:

  • Nunca incluyas JavaScript de fuentes no confiables
  • Usa atributos defer o async para scripts
  • Considera Content Security Policy (CSP) para mayor seguridad

Accesibilidad (A11y)

1. HTML Accesible

  • Usa etiquetas semánticas correctamente
  • Provee texto alternativo para imágenes
  • Usa aria-* attributes cuando sea necesario
  • Implementa una estructura de encabezados lógica

2. Contraste Adecuado

Asegura suficiente contraste entre texto y fondo:

/* BUENA PRÁCTICA - Contraste adecuado */ color: #333; background: #fff; /* Ratio 12.6:1 */ /* MALA PRÁCTICA - Contraste insuficiente */ color: #999; background: #fff; /* Ratio 2.84:1 */

3. Navegación con Teclado

Asegúrate que:

  • Todos los elementos interactivos sean accesibles con TAB
  • Usa :focus-visible para estilos de enfoque
  • Evita outline: none sin proporcionar alternativa

Errores Comunes de Accesibilidad

  • Usar divs como botones sin roles ARIA
  • Formularios sin etiquetas asociadas
  • Contenido que depende exclusivamente del color
  • Tamaños de fuente absolutos sin opción de aumentar

Conclusión

Resumen de Buenas Prácticas

HTML

  • Usa semántica apropiada
  • Estructura lógica de contenido
  • Atributos alt en imágenes
  • Validación W3C

CSS

  • Organización modular
  • Prefiere clases sobre IDs
  • Variables CSS para consistencia
  • Diseño mobile-first

Seguridad

  • HTTPS para recursos externos
  • Atributos rel en enlaces externos
  • Evita CSS/JS inline
  • SRI para CDNs
